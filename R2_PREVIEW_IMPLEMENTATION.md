# Campervan Trip Companion — R2 private media implementation

This patch moves **new Shared Trip Memory photos** and **Today Highlight photos** to the Preview R2 bucket. Existing Google Sheets memory rows, `photo_ids` values, KV highlight records, and Google Drive photos remain readable.

## Files in this patch

- `worker/index.ts` — private R2 upload and authenticated read paths; D1 metadata writes to the existing `trip_media` table.
- `src/App.tsx` — memory photo links now use the authenticated Worker endpoint; Today Highlight copy reflects private trip storage. Includes the current compact Expenses UI file from the latest UI patch.
- `wrangler.jsonc` — Preview-only D1 and R2 bindings, retaining the existing Preview KV binding. Root/production bindings are not changed.
- `migrations/0002_trip_collaboration.sql` — reference copy of the existing migration supplied by the project owner. It is included for consistency; it is not a new migration.

## Legacy South Island bridge

On the first R2 media upload for `nz-south-island`, if the D1 `trips` row does not yet exist, the Worker creates the D1 trip record from the existing configured South Island workbook. It also inserts the previously confirmed initial Admin membership for `koochanyee@gmail.com` (Ralph). It does not assign June an Admin role. This is a one-time bridge for the existing workbook, not a general trip-registration UI.

The current app's existing approved-email gate remains in place. Full per-trip membership authorization and invitation UI are a separate collaboration milestone; this patch does not claim those controls are complete.

## Upload behaviour

- Memory photos: up to 4 per memory, 10 MB maximum each.
- Today Highlight: 4 MB maximum.
- Allowed formats: JPEG, PNG, WebP, GIF, HEIC and HEIF.
- Object keys are generated by the Worker; the browser never chooses an R2 key.
- D1 stores the object key, uploader Google subject, content type, filename, size and creation time.
- If the D1 metadata insert fails, the just-uploaded R2 object is deleted.
- If a later photo in a memory upload fails, previously uploaded photos in that request are rolled back.
- If the Google Sheets memory append fails, the new R2 objects and D1 rows are rolled back.
- New photos are served from R2 only through authenticated Worker endpoints.
- Existing Google Drive photo IDs are detected by the absence of a matching D1 media row and continue through the legacy Drive retrieval path.

SELECT media_type, COUNT(*) AS files, SUM(size_bytes) AS total_bytes
FROM trip_media
GROUP BY media_type;

SELECT media_id, trip_id, uploader_google_sub, object_key, file_name,
       content_type, size_bytes, created_at
